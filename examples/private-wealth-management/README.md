# Second Worked Scenario: Private Wealth Management

*Demo data for Silverline Private Wealth (fictitious company).*

A second, self-contained worked example, structured identically to the
primary Meridian Retail Group scenario at the repository root, to show that
the same TOGAF artifact templates generalize across industries.

## Scenario

Silverline Private Wealth (SPW) is a fictitious independent multi-family
office / registered investment advisor. It is running a program to unify
household reporting, planning, and advisor workflows onto one platform, in
part to integrate the 2026 acquisition of Birchwood Wealth Partners
(whose legacy Foxglove PMS is being retired) and to meet SEC
books-and-records and fiduciary requirements.

## Scope note

This scenario is intentionally **lighter** than the primary Meridian Retail
Group example: one catalog, one matrix, and one diagram per architecture
domain (Business/Data/Application/Technology). The other ADM phases keep
one artifact each — Migration Planning, Implementation Governance, Change
Management, Requirements Management, and Risk & Security — except
Preliminary, Architecture Vision, and Opportunities & Solutions, which
carry two apiece (principles + capability assessment; vision + stakeholder
map; gap analysis + solution building blocks), the same pairing the
primary scenario uses for those three phases. This is lighter than the
fuller depth (multiple catalogs, matrices, and diagrams per domain) built
out for Meridian Retail Group. The goal here is breadth of artifact
*types* across a different industry, not exhaustive depth.

## Structure & conventions

Same folder-per-ADM-phase layout, frontmatter schema, ID scheme, and
Mermaid-only diagram rule as described in the repository root
[README.md](../../README.md). IDs in this scenario are prefixed `PW-` to
keep them visually distinct from the root scenario's IDs — this is a
convenience, not a requirement, since the two scenarios never share a file.
